# Hunter v1.9.0

기존 사내 인증 세션으로 업무 화면에 자동 진입하고, 관리자가 선택한 방문 통계를 격리된 코드로 연결합니다. 일반 PostgreSQL·네 환경변수·서비스 Docker 이미지 하나의 기본 배포를 유지합니다.

## 사용자가 달라지는 점

- 유효한 Hunter 세션은 인증 서버 조회 없이 원래 화면으로 이동합니다. OIDC 자동 진입을 켜면 기존 IdP 세션을 prompt=none으로 확인하고 로그인 폼 없이 원래 메뉴·목록 조건으로 돌아갑니다.
- 인증·동의가 필요하면 로컬·명시 SSO 로그인을 선택합니다. 자동 시도10분·명시 로그아웃24시간 억제와 `/login?local=1` 복구를 제공합니다.
- 관리자 서비스 설정의 방문 추적에서 공개 코드·허용 원점을 검토하고 저장 전 격리 미리보기를 실행합니다. 숫자 revision으로 동시 수정을 감지합니다.
- 방문 추적은 기본 꺼짐이며 일반 페이지의 고정 경로·제목만 별도 프레임에 전달합니다. 로그인·관리자·개인화 페이지는 제외하고 추적 로드 오류는 일반 업무와 분리합니다.

## 운영 조건과 한계

[공식 ReSSO](https://github.com/hkjang/ReSSO)의 OIDC·prompt=none 지원 소스와 설정 계약을 확인했습니다. 실제 운영 계정 연결 검증은 미수행이며 상세 근거는 공식 조사 문서에 기록했습니다. 브라우저가 IdP 주소 자체에 연결하지 못하면 자동 callback 복귀를 보장할 수 없어 Hunter 로컬 복구 주소를 직접 열어야 합니다.

추적은 관리자 브라우저 세션 전용이며 코드32KiB·script태그10개·정확한 원점10개로 제한합니다. 쿠키·스토리지·부모 DOM·eval·iframe에 의존하는 분석 SDK는 페이지 이벤트 어댑터가 필요합니다. 브라우저의 IP·User-Agent 등 기본 HTTP 정보는 수집 시스템에서 관측될 수 있습니다. 미리보기 준비는 실제 접수나 통계 정확성을 보장하지 않습니다.

## 검증과 배포

실제 격리 PostgreSQL의 전체 기본 Go race 회귀는 상위153개·하위99개(252개)를 1160.324초에 통과했습니다. 이후 추가된 로그아웃 DB 실패·추적 동시성/원점·issuer 원문 보완은 마지막 집중 race 검사 상위14개·하위32개(46개), 112.848초로 별도 확인했습니다. 두 집합은 겹쳐 합산하지 않으며 최종 게시 커밋의 전체 CI와 구분합니다. 상세는 [검증 기록](validation.md)에 반영합니다. 로컬 서명 OIDC·수집기 시험은 외부 ReSSO 계정이나 운영 분석 서비스의 실제 수신 검증과 구분합니다. 최종 게시 커밋 CI와 공개 아카이브 다운로드 검증은 실제 완료한 뒤 [릴리즈 본문](https://github.com/hkjang/hunter/releases/tag/v1.9.0)에 기록합니다.

최종 로그인·SSO·방문 추적 화면10장을 반영했습니다. 사용자55쪽·관리자92쪽 PDF의 한글과 새 안내 문구를 추출했고, 갤러리87개·FAQ34개 및320/390/1512px 문서12화면에서 가로 넘침·이미지·스크립트·외부 자원 오류가 없었습니다.

**최종 로컬 후보 검증:** 51,543,034바이트 아카이브(SHA-256 `8fa228da0a302e8e2d68b88be0070a1d904cff3aa2cfc69c26017ddf85405253`)를 오프라인 내부망에서 반입해 브라우저37개·재시작16개 묶음과 같은 이미지의 고정 프로브3종을 통과했습니다. 알림4·자동화10·플랫폼6·추적5개는 브라우저37개에 포함됩니다. 화면68장·라이선스 고지231파일·증거89파일 해시를 확인했고 네 환경변수·비루트·읽기 전용·호스트 소켓/볼륨 없음 조건을 유지했습니다. 전용 컨테이너·네트워크·프록시와 임시 비밀파일을 정리했습니다.

이는 **로컬 후보 이미지**와 내부 모의 서버의 결과입니다. 이전 후보의 실패 증거를 별도로 보존했으며 실제 운영 ReSSO 세션이나 GitHub 공개 다운로드 파일의 검증으로 대체하지 않습니다. 공개 릴리즈 파일은 게시 후 별도 확인합니다.
