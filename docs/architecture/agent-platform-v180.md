# Hunter v1.8 에이전트 연동·복구 설계

Hunter v1.8의 관리자 설정, 데이터 보존, 장애 복구와 실행 경계를 설명합니다. 실제 배포·외부 공급자 운영 검증 여부는 [검증 기록](../validation.md)에서 구분합니다. 선택 연동은 Hunter 서비스에 포함된 어댑터로 연결하며, 외부 공급자나 관측 도구의 전체 서버 스택은 번들하지 않습니다.

## 제공 범위와 실행 경계

외부 검색, 지식 메모리, 모델 공급자, 격리 진단 실행, 관측성 연동을 관리자 화면에서 설정·시험합니다. 네 환경변수와 일반 PostgreSQL만으로 기본 서비스가 시작되며 선택 연동의 장애는 기본 자산·발견 건·진단·알림 기능을 중단하지 않습니다.

| 기능 | 실제 연결 | 기본 구성에서의 동작 |
| --- | --- | --- |
| 검색 | DuckDuckGo 요약, Google CSE, Tavily, Perplexity, SearXNG, HTTP JSON | 외부 검색 비활성, 내부 서비스·발견 자료 사용 |
| 메모리 | 암호화 로컬 기억, 선택 임베딩·Graphiti·설치된 pgvector | 일반 PostgreSQL의 로컬 기억·검색 유지 |
| 모델 | OpenAI 호환 Chat, Anthropic Messages, Gemini, Ollama native | 새 공급자 목록 비활성, 기존 AI 설정 사용 |
| 격리 진단 | 관리자가 등록한 mTLS Docker 서버와 고정 프로브 | 격리 실행 비활성, 기존 내장 진단 유지 |
| 관측성 | OTLP HTTP 수집기와 Langfuse OTLP | 외부 전송 비활성, 내부 실행·감사 기록 유지 |

검색 결과는 출처가 있는 비신뢰 참고 자료로 취급합니다. 실행에는 승인된 서비스·범위·정책을 적용한 고정된 조회·진단 프로파일을 사용합니다. 검색된 익스플로잇이나 임의 셸 명령을 자동 실행하는 기능, Metasploit 공격 모듈의 자율 선택·실행은 연결하지 않습니다. 공격 도구 전체 또는 특정 개수의 설치를 이 기능의 완료로 표현하지 않습니다.

## 공통 관리자 API

기본 경로는 `/api/agent-platform/{group}`이며 group은 `search`, `memory`, `models`, `execution`, `observability`입니다.

- `GET`: `{config, updated_at}`. 비밀값은 빈 문자열과 `*_configured` 여부만 반환합니다.
- `PUT`: `{config, expected_updated_at}`. GET의 `updated_at`을 전달하며 저장 버전이 다르면 409입니다. 화면은 입력을 보존합니다. 검색·메모리의 성공 응답은 `{updated_at}`, 나머지 그룹은 갱신된 `{config, updated_at}`입니다.
- `POST /test`: 저장된 공급자 ID와 `expected_updated_at`, 해당 규격의 시험 입력을 사용합니다. 저장하지 않은 임의 설정으로 시험하지 않습니다. 연결 시험은 실제 API 요청이며 시간 제한·결과와 소요 시간을 표시합니다. 오래된 설정 버전은 외부 요청 전에 409로 거부합니다.
- `GET /status`: 공급자별 정상·미확인·차단·복구 대기와 최근 검사 결과를 표시합니다. 모든 경로는 현재 `admin:manage`를 검사합니다.

설정은 `agent_platform_config`에서 전체 JSON을 암호화하고 revision을 보존합니다. 공급자 ID를 유지한 비밀값의 빈 입력은 유지, 명시적 clear는 삭제, 새 입력은 교체입니다. 메모리는 같은 embedding·Graphiti 슬롯을 기준으로 비밀을 유지합니다. 배열 순서로 비밀값을 결합하지 않습니다.

설정 변경은 DB 잠금 안에서 현재 버전과 비밀 병합을 확인합니다. 네트워크 요청은 이 잠금 밖에서 수행합니다. 입력 검증 오류는 400, 버전 불일치는 409이며 DB·암호화 오류의 원문은 응답에 노출하지 않습니다.

복구 상태는 그룹·공급자·설정 버전별로 관리합니다. 화면의 최초 값은 연속 실패 3회·회복 대기 30초이며, 관리자가 변경할 수 있습니다. 실행 서버 API는 이 두 값을 명시해야 합니다. 차단된 공급자의 회복 대기 이후에는 한 개의 시험 요청만 허용합니다. 상태 코드는 안전한 분류 문자열이며 비밀·요청·응답 본문을 기록하지 않습니다. 설정 revision을 바꾸면 과거 장애 상태와 시도 결과를 새 설정에 적용하지 않습니다. 연결 시험도 같은 상태 관리에 포함합니다.

Graphiti 시험은 합성 그룹의 조회 규격, 격리 실행 시험은 Docker 버전·네트워크·선택 이미지의 존재를 확인합니다. 두 시험은 각각 원격 기억의 색인 완료나 진단 컨테이너의 실행 완료를 의미하지 않습니다. 모델 시험은 고정된 합성 요청을 보내고, 관측 시험은 제한된 합성 메타데이터만 전송합니다.

## 장애 시 기능별 동작

| 연동 | 실패 시 동작 |
| --- | --- |
| 검색 | 우선순위별 공급자 대체 후 내부 서비스·발견 근거로 계속, 최신 검색 불가를 결과에 명시 |
| 원격 메모리 | 로컬 암호화 메모리를 원본으로 유지. 임베딩·외부 그래프 장애 시 로컬 검색으로 복귀 |
| 모델 | 대체 공급자를 순서대로 시도. 모두 실패하면 근거와 작업을 보존한 재개 가능한 대기. AI가 없는 자산·진단·연동 기능은 계속 |
| 격리 실행 | 생성 전 실패만 다른 실행 서버로 대체. 이미 시작되었거나 결과가 불명인 작업을 자동 중복 실행하지 않음 |
| 관측성 | 비동기 대기열·유한 재시도·대체 수집기. 원격 수집 실패가 업무 요청을 실패시키지 않음 |

모델 요청의 일부 답변을 다른 모델의 답변과 합치지 않습니다. 공급자 응답이 성공적으로 완료된 뒤 사용자 응답을 확정하고 도구 실행을 연결합니다. 현재 역할·개인 키·서비스 권한과 긴급 중지는 재시도·복구에도 다시 검사합니다.

## 서비스 망과 실행 컨테이너

실행 서버의 `service_network`는 Hunter 서비스·현재 워커의 망과 정확히 대조하는 분류입니다. 한글을 포함할 수 있으며 trim 이후 200 UTF-8바이트 이내여야 합니다. 별도의 `network`는 Docker에 이미 생성된 ASCII 네트워크 이름입니다. 예를 들어 서비스 망은 `업무망`, Docker 망은 `hunter-sandbox`로 설정합니다. 기존 설정과의 호환을 위해 `service_network`가 비어 있으면 `network`를 서비스 망으로도 사용합니다.

관리자는 digest로 고정한 같은 Hunter 이미지를 실행 서버에 미리 반입합니다. 서버는 자동으로 이미지를 pull하지 않습니다. 프로브는 HTTP 헤더·TLS 인증서·TCP 연결의 고정된 읽기 동작만 수행합니다. 현재 서비스·범위·정책과 망을 확인한 뒤 비특권·읽기 전용·권한 제거·마운트 없는 컨테이너에서 실행합니다. 관리자 연결에는 검증된 HTTPS와 mTLS를 사용하며 호스트 Docker 소켓을 Hunter 제어 컨테이너에 마운트하지 않습니다.

컨테이너 생성 뒤 접수 여부가 불명확하면 같은 서버·컨테이너를 조회합니다. 다른 서버에서 새 작업을 자동 생성하지 않습니다. 완료 결과 뒤 정리에 실패하면 결과를 보존하고 정리를 재시도합니다. 이 상태에서도 기존 내장 진단과 나머지 업무 기능은 독립적으로 운영됩니다.

## 실제 모듈과 데이터 경계

`agent_platform.go`는 암호화 설정·revision·회로 상태를, `agent_search*.go`·`agent_memory*.go`는 검색·로컬 원본 기억을 담당합니다. `agent_models*.go`는 네이티브 모델과 응답 커밋, `agent_telemetry*.go`는 메타데이터 outbox, `agent_execution*.go`는 승인된 고정 프로브를 연결합니다. `agents_control.go`와 `internal/pentagicore/checkpoints.go`는 명시 재개·추가 입력·도구 영수증을 보존합니다. `graphql*.go`와 `agent_reports*.go`는 현재 권한의 조회·보고서 API입니다.

원본 312파일은 보존하며 새 기능은 Hunter 계층과 bridge에서 연결합니다. 같은 PostgreSQL이 준비되어 있으면 선택 연동이 꺼져 있거나 접근 불가여도 기본 서비스는 운영됩니다. 검색·원격 그래프 자료는 권한이나 실행 지시를 늘리지 않습니다. 모델 응답은 성공 검증 후 커밋하므로 실패 제공자의 부분 답변·도구를 다음 제공자와 혼합하지 않습니다.

일시 중지·모델 연결 대기·입력 대기는 같은 ID의 체크포인트를 명시 재개합니다. 사용자 제어 revision은 `control_updated_at`이며 요청 `expected_updated_at`에 전달합니다. 실행 로그의 진행만으로 이 제어 버전은 바뀌지 않으며 현재 `updated_at`을 보내는 기존 호출도 호환 처리합니다. 현재 상태·원래 실행 주체·키·서비스·범위·정책은 재개 때 다시 검사합니다. 모델·Hunter 도구 호출 및 활성 시간은 누적하고, 원본 역할 체인 반복은 호출별 한도를 적용하므로 재개에 따른 새 호출에서 반복 횟수는 다시 시작합니다. 완료 도구의 영수증은 같은 호출의 중복 실행을 막습니다. 종료·프로세스 강제 종료의 무조건 자동 재실행은 없습니다.

로컬 메모리·벡터·추가 입력·도구 영수증·모델 signature·관측 outbox는 암호화합니다. 원본 호환 스키마의 비공개 대화·체크포인트에는 별도 필드 암호화가 없으므로 DB와 백업 접근 통제가 필요합니다. 원격 Graphiti의 과거 episode 삭제, 모델 signature 이력의 자동 보존 파기는 별도 제공하지 않습니다.

관측 전송은 허용된 실행 식별자·상태·호출 수·시간 메타데이터만 사용하며 프롬프트·도구 입력·응답·증거 원문을 포함하지 않습니다. 수집기의 재시도 때문에 같은 메타데이터가 여러 번 도착할 수 있지만 진단 도구를 다시 실행하지는 않습니다. 로컬 큐는 유한한 재시도와 보존 기간을 적용합니다.

## 조회와 실행 보고서

GraphQL은 인증 후 `/api/graphql`에서 조회만 제공합니다. 자료별 현재 키·역할·팀·부모 서비스 권한을 확인하며 깊이 8, 확장 필드 500, 복잡도 10,000과 페이지 크기 100으로 요청을 제한합니다. mutation·subscription·배치 요청은 지원하지 않습니다. 스키마 조회와 introspection에도 인증이 필요합니다.

성공 JSON 응답 전체에 4MiB 예산을 적용합니다. projection 단계에서 응답 별칭·문자열의 UTF-8/JSON escape·구조 문자와 봉투를 보수적으로 누적하여 초과 전에 중단합니다. 초과 시 HTTP 400의 `QUERY_LIMIT`, `data:null`과 고정 오류만 반환하고 부분 데이터를 전송하지 않습니다. 숫자 등 일부 값은 최대 인코딩 길이를 사용하므로 경계에서 여유를 두고 조회해야 합니다. 응답 크기 제한은 기존 현재 권한 검사와 별도로 적용합니다.

`/api/agent-runs/{id}/report?format=md|html|pdf`는 현재 접근 가능한 실행의 목표·상태·한도·작업·연결 진단·마스킹한 결과를 내려받습니다. 진행 중·대기·실패 상태도 그대로 표시하며 완료나 해결로 바꾸지 않습니다. HTML은 이스케이프와 CSP를 적용하고, PDF는 Go 라이브러리와 이미지에 포함한 한국어 폰트를 사용하여 외부 브라우저·프로세스 없이 생성합니다. 화면·보고서의 조회에는 기존 에이전트 읽기 4개 범위가 모두 필요합니다.

연결 규격·상한·검증 해석은 [관리자 가이드](../guides/admin-guide.md#145-에이전트-연동-관리-공통-절차)와 [공식 프로토콜 조사](../research-agent-platform.md)를 참조합니다.
