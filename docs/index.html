QUESTIONS, ANSWERED

도입 전에 궁금한 점.

Hunter는 어떤 서비스인가요?

Hunter는 사내 서비스를 대상으로 자산, 승인된 진단, 취약점 발견 건, 개선 상태와 재검증을 연결하는 보안 검증 플랫폼입니다. Go 서버와 React 화면, PostgreSQL로 구성되며 내부 조직의 운영 환경에 맞춰 설정할 수 있습니다.

인터넷 없이 사용할 수 있나요?

서비스 이미지를 반입하면 외부 CDN 없이 화면과 서버를 실행합니다. PostgreSQL은 사내에 별도 준비하고, OIDC·AI를 사용하려면 해당 사내 서버에 접근할 수 있어야 합니다. 이미지 빌드와 외부 스캐너 데이터 갱신은 승인된 별도 반입 과정이 필요합니다.

배포 환경변수는 무엇인가요?

POSTGRES_DSN, BOOTSTRAP_ADMIN, BOOTSTRAP_ADMIN_PASSWORD, ENCRYPTION_KEY 네 가지입니다. 서비스 이름, OIDC, AI, 세션, 역할 권한과 연동 설정은 관리자 화면에서 관리합니다.

Keycloak SSO 연결에 어떤 설정이 필요한가요?

일반 설정에서 서비스 공개 주소를 저장하고 OIDC 설정에 realm issuer, client ID, client secret을 입력합니다. Keycloak에는 서비스의 /api/auth/oidc/callback 주소를 등록합니다. Discovery를 통해 인증 엔드포인트와 서명키 정보를 가져옵니다.

모든 취약점 스캐너가 이미지에 포함되나요?

제한된 HTTP 헤더 점검과 권한 시나리오 실행을 제공합니다. Nuclei, Trivy, ZAP, Semgrep 계열 SARIF, Gitleaks는 외부에서 승인된 절차로 실행한 결과를 가져옵니다. 외부 스캐너 바이너리나 취약점 DB는 서비스 이미지에 포함하지 않습니다.

검토·승인 프로세스가 꼭 필요한가요?

관리자 설정에서 활성화한 경우에만 팀장 검토·승인·반려 흐름이 적용됩니다. 비활성화하면 해당 업무 단계와 승인 메뉴가 제외됩니다. 진단 대상의 명시적 승인과 유효한 범위는 설정과 관계없이 항상 필요합니다.

AI가 자동으로 진단 명령을 실행하나요?

관리자가 에이전트를 켜면 PentAGI 코어가 계획·위임을 진행하며 여덟 Hunter 도구를 호출합니다. 참고 검색은 비신뢰 자료이며 실제 진단은 별도 허용·현재 사용자·대상 승인·범위를 검사합니다. 격리 실행도 같은 Hunter 이미지의 고정 읽기 프로브이며 임의 셸·공격 모듈을 실행하지 않습니다.

PentAGI 통합에도 별도 서비스가 필요한가요?

MIT 원본 코어와 기존 PostgreSQL로 기본 서비스를 실행합니다. 검색·임베딩·Graphiti·모델·격리 실행·관측은 관리자 선택 연동이며 기본 꺼짐입니다. 선택 서버는 조직에서 준비하지만 네 환경변수와 서비스 이미지 하나의 배포 방식을 유지하고 원본 외부 스택을 자동 기동하지 않습니다.

원하는 메뉴와 항목을 빨리 찾으려면 어떻게 하나요?

Ctrl+K 빠른 이동에서 한글 메뉴명, 영어 별칭과 초성으로 메뉴를 검색합니다. 자주 쓰는 메뉴는 브라우저에 사용자별 즐겨찾기로 저장합니다. 목록에서는 검색·필터·열 정렬·페이지 이동을 사용하고, 조건은 URL에 보존되어 새로고침 후에도 유지됩니다. 목록 탐색은 현재 조회한 자료 범위 안에서 동작합니다.

자주 쓰는 목록 조건과 표 모양을 저장할 수 있나요?

저장한 보기에 검색·필터·정렬·표시 수를 사용자·메뉴별 최대 8개 저장합니다. 같은 브라우저에서 다시 선택하면 첫 페이지부터 표시하며 다른 기기로 자동 동기화되지 않습니다. 표 표시 설정에서 글자 크기를 유지한 채 행 간격을 줄이거나 전체 표를 펼칠 수 있습니다. 펼친 표를 문서와 함께 스크롤할 때는 헤더가 고정되지 않습니다.

폐쇄망에서 SBOM과 위협 정보를 어떻게 갱신하나요?

관리자가 승인된 경로로 확보한 KEV JSON·EPSS CSV를 반입하고 기준일·건수·해시를 확인합니다. 서비스의 CycloneDX·SPDX JSON 명세도 파일로 반입해 구성요소와 버전 변화를 확인합니다. 런타임에 외부 피드를 자동 다운로드하지 않으며 오래된 자료와 정보 없음을 구분합니다.

조치함 점수와 라이선스 검토는 어떤 의미인가요?

조치함은 현재 접근 가능한 미조치 발견 건에 SLA와 심각도·서비스 중요도·KEV·EPSS를 이용한 운영 우선순위를 표시합니다. 점수는 CVSS나 침해 확률이 아니며 발견 상태를 변경하지 않습니다. SBOM 라이선스 표시는 조직의 검토 목록과 선언 정보에 따른 검토 대상 표시이며 법적 적합성 판단은 아닙니다.

캠페인 비교에서 사라진 발견 건은 해결된 건가요?

아닙니다. 미관측은 기준 실행에 있던 결과가 이번 결과에 없다는 뜻이며 상태를 변경하지 않습니다. 같은 대상·정책·인증 조건과 버전으로 완료한 내장 진단만 비교합니다. 외부 반입, 이전 버전, 실패·취소·조건 변경 결과는 비교 불가로 표시하고 기존 재검증 절차로 해결을 확인합니다.

발견 건 여러 개를 한 번에 변경할 수 있나요?

발견 건과 조치함에서 현재 페이지의 최대 100개 항목을 선택해 담당자·수동 기한·허용된 진행 상태를 바꿉니다. 각 항목의 현재 권한과 조회 버전을 다시 검사하며 한 항목이라도 충돌하면 전체 취소합니다. 해결·오탐·위험 수용은 개별 검토 절차를 유지합니다.

다른 사람과 동시에 수정하면 어떻게 되나요?

일반 자원 수정은 편집을 시작한 자료의 변경 시각을 함께 보냅니다. 충돌하면 내 입력을 유지하고 최신 자료를 확인한 뒤 명시적으로 재작성하도록 안내합니다. 모든 관리자 설정이나 워커의 별도 저장 API까지 같은 버전 비교를 제공하는 것은 아닙니다.

같은 대상을 다시 진단하거나 탭별 조건을 보관할 수 있나요?

같은 대상으로 새 캠페인을 선택하면 현재 접근 권한을 다시 확인하고 검토용 초안을 만듭니다. 등록 후 별도로 시작하며 이전 결과는 복사하지 않습니다. SBOM·캠페인의 탭별 검색·정렬·페이지와 비교 기준을 보관하고, 소프트웨어의 서비스 필터도 저장한 보기에서 복원합니다.

발견 건과 진단 결과를 이메일·문자로 받을 수 있나요?

관리자 알림센터에서 SMTP·문자·카카오톡·HTTP 채널과 고정 또는 담당자·조직·당직 수신자를 설정합니다. 발견·기한·진단·승인 이벤트에 영업일 예고·미확인 대응·주간 요약을 추가해 아홉 이벤트를 지원합니다. 필요한 자동화만 활성화하며 PostgreSQL 대기열과 네 환경변수를 유지합니다.

알림톡이 모든 공급자와 바로 연결되나요?

공급자 또는 사내 게이트웨이의 인증·본문·성공 응답을 설정해야 합니다. 등록 발신번호, 발신프로필과 승인 템플릿은 조직에서 준비하며 공급자별 토큰·메시지 정책이 다릅니다. 폐쇄망에서는 조직이 허용한 중계 경로가 필요합니다.

게이트웨이 접수는 실제로 알림을 받았다는 뜻인가요?

SMTP 릴레이 또는 API가 요청을 접수했다는 뜻입니다. 별도 공급자 결과 조회·Hunter 서명 콜백으로 전달 상태를 연결할 수 있고, 개인 업무 확인과 팀장 승인은 다시 별도입니다. 결과 불명·충돌을 자동 재전송하지 않으며 같은 전달 ID에 receipt가 있으면 수동 재시도도 차단합니다.

담당자가 바뀌거나 당직 시간이 끝나면 수신자도 바뀌나요?

관리자가 확인한 연락처와 규칙의 수신자 소스를 기준으로 현재 담당자·서비스 소유자·조직·당직을 다시 계산합니다. 현재 계정·역할·서비스 접근 권한을 검사하며 권한을 잃은 사용자에게 과거 주소로 계속 발송하지 않습니다. 연락처의 확인 표시는 관리자 확인이며 자동 OTP 인증은 아닙니다.

내 업무 알림의 확인은 승인과 같은가요?

아닙니다. 나에게 지정된 현재 접근 가능한 업무 내용을 확인했다는 기록입니다. 알림 전달·읽음·팀장 승인·취약점 해결과 별도로 관리합니다. 업무 확인과 미확인 규칙을 켠 경우에만 확인 기한 뒤 후속 알림이 생성됩니다.

알림이 실패하면 다른 채널로 자동 발송하나요?

명시적인 전달 실패가 확인되고 관리자가 대체 채널을 설정한 경우에만 같은 수신자 계열로 한 단계 한 번 요청합니다. 불명확한 응답·조회 불가·결과 충돌은 실패로 추정하지 않습니다. 현재 채널·규칙·수신자 권한을 다시 검사합니다.

코드 변경 시 어떤 진단이 실행되나요?

관리자가 실제 경로·API·구성요소·권한 변경 목록과 프로파일·시나리오를 연결합니다. 서명과 멱등 참조를 검증한 뒤 매칭된 검사만 현재 범위·정책으로 요청합니다. Git 원본 콜백은 Hunter 형식으로 변환·재서명해야 하며 외부 SAST·컨테이너 엔진을 자동 설치하거나 실행하지 않습니다.

ITSM 티켓을 완료하면 취약점도 해결되나요?

외부 완료만으로 해결하지 않습니다. 외부 티켓의 담당자·기한·상태를 조회나 서명 콜백으로 동기화하며 로컬 수정 충돌을 보존합니다. 명시적인 배포 확인과 관리자 옵션이 있을 때 현재 정책이 허용하는 재검증을 요청하고 실제 결과로 해결을 판단합니다.

자동화 규칙을 발송 없이 시험하거나 본문을 정리할 수 있나요?

모의 검사는 보관된 이벤트를 현재 규칙·자료·수신자 권한으로 평가해 예상 건수와 제외 사유를 보여주며 외부 발송하지 않습니다. 보존 정책은 적격 종결 건의 본문·수신 정보·시도 상세를 파기하고 중복 식별 기록을 유지합니다. 진행·불명·미확인·보존 고정 건과 백업 사본은 별도 취급합니다.

여러 모델을 연결하고 장애 시 바꿀 수 있나요?

OpenAI 호환·Anthropic·Gemini·Ollama native 모델을 역할별 순서와 우선순위로 연결합니다. 실패한 부분 응답을 버린 뒤 다음 연결을 시도하고 완성 답변만 커밋합니다. 모든 연결이 불가하면 에이전트는 연결 대기에 남고 일반 업무는 계속됩니다. 최대 262,144 설정과 실제 모델 한도를 함께 적용합니다.

진행 중 지시를 추가하거나 같은 실행을 이어갈 수 있나요?

추가 입력을 저장하고 안전 경계에서 일시 중지할 수 있습니다. 일시 중지·입력 대기·모델 연결 대기는 원래 키·현재 서비스·범위·정책과 누적 예산을 검사한 뒤 같은 실행 ID를 명시 재개합니다. 종료·프로세스 강제 종료를 무조건 자동 재실행하는 기능은 아닙니다.

검색·Graphiti·pgvector를 반드시 설치해야 하나요?

선택 기능입니다. 검색은 비신뢰 참고이며 실패하면 내부 근거를 사용합니다. 기억은 사용자·서비스별 암호화 로컬 자료가 원본이고 원격 그래프 문장을 그대로 반환하지 않습니다. pgvector가 없으면 로컬 cosine·키워드로 복귀하며 확장을 자동 설치하지 않습니다.

격리 진단은 어떤 컨테이너를 실행하나요?

관리자가 mTLS 서버와 승인된 같은 Hunter 이미지 digest를 등록합니다. 서비스 망과 별도 Docker 네트워크를 지정하고 고정 HEAD·TLS 인증서·TCP 연결 프로브를 제한 실행합니다. 임의 셸·공격 도구 번들·자동 이미지 다운로드는 없으며 생성 이후 결과가 불명인 작업을 중복 실행하지 않습니다.

관측 서버에 프롬프트와 증거가 전송되나요?

호출 수·소요 시간·안전한 식별자 같은 메타데이터만 암호화 대기열에서 OTLP·Langfuse로 전송합니다. 프롬프트·도구 인자·결과·증거는 관측 payload에서 제외합니다. 수집 장애는 업무 응답과 분리하며 Jaeger·VictoriaMetrics·Loki 같은 서버를 번들하지 않습니다.

GraphQL과 실행별 한국어 보고서도 제공하나요?

인증된 읽기 전용 GraphQL로 서비스·발견 건·진단·실행의 허용 필드를 조회합니다. introspection도 인증하고 페이지·깊이·복잡도를 제한합니다. 실행별 MD·HTML·한국어 PDF에는 현재 진행·대기·실패와 실제 결과를 그대로 표시하며 내장 폰트로 오프라인 생성합니다.

기존 SSO 세션으로 로그인 화면 없이 들어갈 수 있나요?

관리자가 OIDC와 자동 진입을 켜면 prompt=none으로 기존 인증 세션을 확인해 원래 업무 화면으로 돌아갑니다. 추가 인증·동의가 필요하면 로컬 또는 명시 SSO 로그인을 선택합니다. 자동 시도는 10분, 로그아웃은 24시간 자동 재시도를 억제하며 /login?local=1로 복구할 수 있습니다.

ReSSO와 바로 호환된다고 볼 수 있나요?

공개 hkjang/ReSSO의 OIDC·prompt=none 지원 소스와 설정 계약을 확인했습니다. 실제 운영 계정 연동 검증은 미수행이며 사내 환경의 연결 확인이 필요합니다. OIDC Discovery·Authorization Code·PKCE S256·서명 ID token과 prompt=none query 응답 지원, callback 등록과 사내 연결 조건을 확인해야 합니다.

관리자가 방문 통계 스크립트를 추가할 수 있나요?

서비스 설정의 방문 추적에서 공개 코드 32KiB와 정확한 원점 최대10개를 등록합니다. 기본 꺼짐이며 별도 sandbox로 일반 메뉴의 고정 경로·제목만 전달하고 로그인·관리자·개인화 화면은 제외합니다. 쿠키·부모 DOM에 의존하는 SDK는 이벤트 어댑터가 필요합니다. 미리보기 준비는 수집 서버의 실제 접수 보장이 아닙니다.
