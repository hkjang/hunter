오프라인 후보 이미지는 Docker `--internal` 네트워크에서 네 환경변수, UID 10001, 읽기 전용 루트, capability 전체 제거, `no-new-privileges`, 마운트 없음으로 실행했습니다. 일반 PostgreSQL의 확장은 기본 `plpgsql`만 사용했고 외부 HTTP 연결은 차단됐습니다. 실제 API로 SBOM·KEV·EPSS 반입, SLA·조치함 점수, 마스킹 댓글, 같은 구성요소의 발견 건 연결, 캠페인 멱등 시작과 비교 불가 처리, 운영 점검, MCP 범위를 확인했습니다. 새 일곱 경로의 데스크톱·모바일 14개 화면과 기존 검색·정렬·저장 보기·빠른 이동·키보드 동작도 통과했습니다. 서비스 재시작 후 새 로그인, SBOM·EPSS·SLA·댓글과 원래 캠페인 진단 ID가 유지됐습니다.

이 오프라인 검사는 최종 게시 전 로컬 후보 이미지에 대한 결과입니다. 이후 OpenAPI 상세 스키마 설명이 보완됐으며 공개 릴리즈는 최종 커밋으로 다시 빌드합니다. 공개 이미지와 게시 결과는 [GitHub Actions](https://github.com/hkjang/hunter/actions)와 해당 릴리즈의 기록으로 확인합니다.

화면의 위협 정보·SBOM·발견 건은 설명용 합성 자료입니다. 캠페인 검증은 승인된 자체 HTTP 대상의 제한된 헤더 검사이며 실제 조직 전체의 취약점 탐지율이나 임의 스캐너의 완전성을 검증한 결과가 아닙니다. 모의 AI 응답과 실패 응답을 사용한 화면 검사는 해당 통합·복구 경로의 검증으로 구분합니다. 신규 설치에 캡처용 데이터나 시험 자격 증명을 넣지 않습니다. 외부 피드 자동 수집, SBOM의 완전한 표준 스키마·라이선스 적법성 인증, 미관측에 따른 자동 종결을 제공한다고 해석하지 않습니다.

목록 경계와 정렬 검사는 브라우저에서 API 응답을 합성 자료로 대체했으며, 변경 요청은 차단했습니다. 이는 화면 동작의 검증이고 서버 권한이나 대규모 DB 조회 성능을 대신하지 않습니다. 실제 세션·로그인과 최종 전체 캡처는 로컬 Go API로 별도 확인했습니다. SSO 복귀의 브라우저 분기는 합성 콜백으로 검사했으며 실제 사내 Keycloak realm의 재검증 결과로 표현하지 않습니다.

검색·정렬·화면 페이지 이동은 API가 반환한 자료에 적용합니다. 리소스는 최신 5,000건, 에이전트·감사는 최신 1,000건까지이며 상한에 도달하면 화면 하단에 범위를 표시합니다. 즐겨찾기·최근 방문은 같은 브라우저의 사용자별 저장소에 보관하고 현재 허용 메뉴만 표시합니다.

이 결과는 로컬 합성 AI를 사용한 실제 코드·도구·저장소·통신 경계의 통합 검증입니다. 실제 LLM의 추론 품질, 취약점 탐지율이나 사내 Keycloak 환경 전체를 검증한 것은 아닙니다. 화면용 합성 데이터·시험 자격증명·모의 서버는 운영 이미지 초기 데이터에 포함하지 않습니다. 원본 Docker 공격 실행기·인터넷 검색·Graphiti 서비스를 기동하는 구성도 아닙니다. AI·에이전트 기능은 관리자 설정에서 기본 비활성화 상태로 시작합니다.

## 인터넷 경로가 없는 Docker 실행

`docker save`로 만든 `hunter-v1.0.0.tar.gz`를 다시 `docker load`하고, Docker의 `--internal` 네트워크에 PostgreSQL, Hunter 서버, 별도 Hunter 워커와 검증 클라이언트를 연결했습니다. 네트워크의 `Internal=true`와 서버의 기본 게이트웨이 부재를 확인했습니다.

서비스는 `hunter:v1.0.0`, UID/GID `10001:10001`, 읽기 전용 루트 파일시스템, 임시 `/tmp`, 모든 capability 제거, `no-new-privileges`로 실행했습니다. 서비스 프로세스에는 요구된 네 개의 설정 환경변수만 전달했습니다.

1. 상태 API의 버전과 초기 관리자 로그인이 정상 동작했습니다.
2. 신규 DB에서 서비스·발견 건 목록이 비어 있어 예시 데이터가 자동 생성되지 않음을 확인했습니다.
3. 별도 워커가 기본 비활성·미분류 망으로 등록된 뒤 관리자 설정으로 활성화되는 것을 확인했습니다.
4. 승인된 자체 검증 컨테이너의 `/api/health`만 범위에 넣고 실제 HTTP 진단을 실행했습니다. 지정한 망의 별도 워커가 작업을 완료했습니다.
5. 조회 권한 개인 키에는 조회 MCP 도구만 노출되었습니다. 키 회전 직후 이전 키는 거부되고 새 키는 동작했으며 폐기도 완료했습니다.
6. 서비스 컨테이너 재시작 후 로그인, 서비스 설정, 개인 시작 페이지, 자산이 보존되었습니다.
7. 같은 내부 네트워크의 Chromium에서 실제 이미지의 로그인·개인 시작 페이지·중첩 경로 새로고침·로컬 폰트·모바일 화면을 확인했습니다. 외부 자산 요청과 JavaScript 오류는 없었습니다.
8. 기존 DB에 다른 암호화 키를 전달한 별도 컨테이너는 시작을 거부하고 종료 코드 1을 반환했습니다.

압축 아카이브의 Docker manifest에는 `hunter:v1.0.0` 이미지 한 개만 포함됩니다. PostgreSQL, 외부 진단 엔진, 문서 압축 파일은 릴리즈 첨부 자산에 포함하지 않습니다. 게시된 최종 아카이브의 SHA-256은 GitHub 릴리즈 본문에서 확인합니다.

## 검증의 적용 범위

- OIDC는 서명된 토큰을 발급하는 로컬 모의 issuer로 discovery·PKCE·nonce·JWT 검증을 수행했습니다. 조직의 실제 Keycloak realm, 인증서, 프록시와 사용자 정책은 설치 환경에서 연결 확인이 필요합니다.
- AI는 OpenAI 호환 모의 스트리밍 서버로 검증했습니다. 262,144 설정 상한은 연결 모델의 실제 컨텍스트·출력 능력을 보장하지 않습니다.
- 내장 진단은 제한된 HTTP 보안 헤더 점검과 사전 정의한 합성 데이터 권한 비교입니다. 외부 스캐너는 승인된 별도 환경에서 실행하고 결과를 가져옵니다.
- 첫 버전의 목록 조회와 그에 기반한 보고서·대시보드·그래프는 권한 범위 안의 종류별 최신 5,000건으로 제한됩니다.
- 본 검증은 모든 조직의 네트워크 구성과 임의 규모의 동시 부하를 대신하지 않습니다. 실제 서비스 도입에는 관리자 가이드에 따라 사내 연결과 승인 범위를 설정합니다.
