### 최종 로컬 후보 이미지의 오프라인 확인

마지막 UI 보완을 포함한 **로컬 후보** `hunter:v1.9.0`을 다시 반입해 검증했습니다. 아카이브 크기는 **51,543,034바이트**, SHA-256은 `8fa228da0a302e8e2d68b88be0070a1d904cff3aa2cfc69c26017ddf85405253`입니다. Docker 이미지 ID는 `73903f00d854cc4a0df30b6277ea982dff93c996a6361213552ee12c2124b81a`입니다. 이는 GitHub에 게시한 파일을 다운로드해 검사한 결과가 아닙니다.

브라우저 **37개 묶음**, 재시작 **16개 묶음**, 같은 실제 이미지의 고정 HEAD·TLS·TCP 프로브 **3종**을 통과했습니다. 알림4·자동화10·플랫폼6·방문 추적5개 묶음은 브라우저37개에 포함되어 별도로 더하지 않습니다. 화면68장, 런타임 라이선스 고지231개 파일과 증거89개 파일의 원본·보존 복사본 SHA-256 일치를 확인했습니다.

네 환경변수만 전달하고 UID10001·읽기 전용 루트·capability 전체 제거·no-new-privileges·Docker 내부 네트워크·일반 PostgreSQL에서 실행했습니다. 호스트 소켓·볼륨 없이 외부 통신 차단을 유지했습니다. 추적 기본 비활성, 설정 암호화, 저장 충돌409, 개인 API 키403, 본문 없는 감사, 한 번 사용하는 미리보기와 opaque iframe의 부모 DOM·쿠키 차단을 확인했습니다. 모바일 OIDC callback 주소 줄바꿈과 재시작 후 설정 보존도 통과했습니다.

### 릴리즈 전 GraphQL 응답 예산 보완

보완한 소스를 실제 격리 PostgreSQL에서 `go test -race -count=1 -run '^TestGraphQL'`로 검사해 상위 5개·하위 20개를 통과했습니다(패키지 26.744초). 신규 예산 검사 3개와 기존 조회·권한 검사 2개가 포함됩니다. 작은 합성 예산의 조기 중단, 긴 저장 결과의 반복 별칭을 사용하는 실제 HTTP 요청의 4MiB 직렬화 전 거부와 1KiB 미만 오류 응답, 정상 조회 200을 확인했습니다. 기존 키·부모 권한·조각·introspection 회귀도 통과했습니다.

성공 JSON 봉투·개행·별칭·구조 문자와 UTF-8/JSON escape를 포함한 총 4MiB 예산을 결과 구성 단계에서 보수적으로 계산합니다. 초과 시 HTTP 400과 `QUERY_LIMIT`, `data:null`만 반환하며 일부 조회 자료를 먼저 내보내지 않습니다. 현재 사용자·키·부모 서비스 권한 검사는 유지합니다. 관리자 가이드와 HTML/PDF에 예산·오류 계약을 반영하고 320·390·1512px의 해당 문서 세 화면을 재검사했습니다. 가로 넘침·이미지·JavaScript·외부 자원 오류가 없고, PDF에서 4MiB·QUERY_LIMIT·data:null 문구를 추출했습니다. 위 기능 통합 단계의 전체 Go 검사와 첫 후보 기록은 이 후속 변경의 검증으로 대체하지 않습니다. 보완 소스의 최종 전체 CI와 공개 릴리즈 이미지 확인은 해당 커밋의 [GitHub Actions](https://github.com/hkjang/hunter/actions)와 릴리즈 본문에서 별도로 기록합니다.

변경·ITSM 검증은 로컬 모의 HTTP 티켓 서버와 합성 자료를 사용했습니다. 재검증 요청 생성과 멱등성을 검사한 시험을 실제 취약점 탐지 성능이나 외부 ITSM 실계정 연동으로 표현하지 않습니다. 화면용 실제 편집 충돌은 임시 미승인 합성 서비스를 두 클라이언트로 수정해 확인한 뒤 삭제했습니다. 승인 화면 예시를 위해 실제 승인 설정을 바꾸거나 외부 수신자에게 발송하지 않았습니다.

최종 로컬 후보 이미지는 Docker `--internal` 네트워크에서 네 환경변수, UID 10001, 읽기 전용 루트, capability 전체 제거, `no-new-privileges`, 마운트 없음으로 실행했습니다. 외부 통신 차단, PostgreSQL 기본 `plpgsql` 확장만 사용, 런타임 라이선스 고지 224개 파일을 확인했습니다. 실제 내장 화면의 브라우저 26개 검사 묶음과 재시작 13개 묶음을 통과했으며 화면 50장과 증거 60개의 SHA-256을 확인했습니다. 새 자동화 10개와 기존 알림 4개 묶음은 브라우저 26개에 포함된 수이며 중복 합산하지 않습니다.

동적 수신자 네 종류의 합집합과 권한 회수 시 취소, 사건 묶음·수신자별 한도·긴급 예외, 실제 발송 없는 모의 검사, 영업일 예고·업무 확인 후속·주간 집계를 확인했습니다. 보존 고정·결과 불명 제외, HMAC 결과 콜백·조회, 한 번의 대체 발송과 장애 회복, 변경 영역·선택 승인, 자동 ITSM 조회·수정 충돌·실제 제한 재진단을 통과한 해결까지 로컬 합성 대상에서 검사했습니다. 최종 후보 첫 실행에서 제품 추가 수정 없이 통과했으며 전용 컨테이너·네트워크·임시 자격 파일을 모두 정리했습니다.

긴 묶음·업무 확인·결과 조회·일시 중단·보존 대기는 실제 미래 시각을 먼저 확인한 뒤 격리 시험 DB의 해당 시각만 조정해 반복 대기를 줄였습니다. 주간 해결 수는 기간 안에 갱신된 현재 해결 상태의 수이며 실제 해결 전환 건수나 MTTR로 해석하지 않습니다. 외부 공급 계정·실수신자·단말 도달·알림톡 승인 템플릿의 실환경 검증은 포함하지 않습니다.

검증한 후보 아카이브는 49,993,923바이트이며 SHA-256은 `ec4c2b9073dddd77394c2f6bc6ccb4de7173e9c1aa7f87697ae3b93e20b2ac8e`입니다. 내장 웹·API 파일 130개를 최종 소스와 대조했습니다. 이 기록은 공개 릴리즈에서 내려받은 파일의 검증과 구분합니다. 게시 파일의 결과는 해당 릴리즈와 [GitHub Actions](https://github.com/hkjang/hunter/actions)에서 별도로 확인합니다.

오프라인 최종 후보는 Docker `--internal` 네트워크에서 네 환경변수, UID 10001, 읽기 전용 루트, capability 전체 제거, `no-new-privileges`, 마운트 없음으로 실행했습니다. 외부 통신 차단, PostgreSQL 기본 `plpgsql` 확장만 사용, 런타임 라이선스 고지 224개 파일을 확인했습니다. 실제 내장 화면의 브라우저 16개 검사 묶음(알림 4개 포함)과 재시작 10개 묶음을 통과했으며 검증 화면 34장을 남겼습니다.

로컬 모의 SMTP·SMS·카카오톡·HTTP 게이트웨이의 자동 접수와 실제 UI에서의 SMTP 시험 요청을 확인했습니다. HTTP 429의 제한된 재시도·취소, 연결 단절·503의 결과 확인 필요 상태, 재시작 후 접수 횟수 유지도 통과했습니다. 429의 실제 미래 재시도 시각을 확인한 뒤 격리된 시험 DB에서 대기 시각만 앞당겨 반복 대기를 단축했습니다. 비밀 암호화·원문 반환 제외, 권한 403과 수정 충돌 409도 확인했습니다. 실제 공급자 계정이나 외부 수신자에게 발송한 검증은 아닙니다. 검증 후 전용 컨테이너·네트워크와 임시 비밀 파일을 정리했습니다.

검증한 로컬 후보 아카이브는 49,674,483바이트이며 SHA-256은 `ae494a3c47eeaeb3ca15c6da651b172853b388a519cdf81b9a9ba2b622556866`입니다. 후보의 내장 API 명세와 웹 자산 130개를 최종 소스와 대조했습니다. 이 기록은 공개 릴리즈에서 내려받은 이미지의 검증 결과와 구분합니다. 게시 이미지의 결과는 해당 릴리즈와 [GitHub Actions](https://github.com/hkjang/hunter/actions)에서 별도로 확인합니다.

게이트웨이 접수는 메일함·단말 도달이나 읽음 확인을 보장하지 않습니다. 실제 공급 계정, 인증서 체인, 발신번호 등록, 알림톡 템플릿 심사·승인과 과금·도달 결과는 별도 사내 연동 확인 대상입니다. 알림 발송은 제어 서버에서 동작하며 진단 전용 `--worker-only` 인스턴스는 발송하지 않습니다. 승인 기능이 꺼진 상태에서 알림 규칙이 승인 프로세스를 새로 만들지 않습니다.

## 인터넷 경로가 없는 Docker 실행

`docker save`로 만든 `hunter-v1.0.0.tar.gz`를 다시 `docker load`하고, Docker의 `--internal` 네트워크에 PostgreSQL, Hunter 서버, 별도 Hunter 워커와 검증 클라이언트를 연결했습니다. 네트워크의 `Internal=true`와 서버의 기본 게이트웨이 부재를 확인했습니다.

서비스는 `hunter:v1.0.0`, UID/GID `10001:10001`, 읽기 전용 루트 파일시스템, 임시 `/tmp`, 모든 capability 제거, `no-new-privileges`로 실행했습니다. 서비스 프로세스에는 요구된 네 개의 설정 환경변수만 전달했습니다.

1. 상태 API의 버전과 초기 관리자 로그인이 정상 동작했습니다.
2. 신규 DB에서 서비스·발견 건 목록이 비어 있어 예시 데이터가 자동 생성되지 않음을 확인했습니다.
3. 별도 워커가 기본 비활성·미분류 망으로 등록된 뒤 관리자 설정으로 활성화되는 것을 확인했습니다.
4. 승인된 자체 검증 컨테이너의 `/api/health`만 범위에 넣고 실제 HTTP 진단을 실행했습니다. 지정한 망의 별도 워커가 작업을 완료했습니다.
5. 조회 권한 개인 키에는 조회 MCP 도구만 노출되었습니다. 키 회전 직후 이전 키는 거부되고 새 키는 동작했으며 폐기도 완료했습니다.
6. 서비스 컨테이너 재시작 후 로그인, 서비스 설정, 개인 시작 페이지, 자산이 보존되었습니다.
7. 같은 내부 네트워크의 Chromium에서 실제 이미지의 로그인·개인 시작 페이지·중첩 경로 새로고침·로컬 폰트·모바일 화면을 확인했습니다. 외부 자산 요청과 JavaScript 오류는 없었습니다.
8. 기존 DB에 다른 암호화 키를 전달한 별도 컨테이너는 시작을 거부하고 종료 코드 1을 반환했습니다.

압축 아카이브의 Docker manifest에는 `hunter:v1.0.0` 이미지 한 개만 포함됩니다. PostgreSQL, 외부 진단 엔진, 문서 압축 파일은 릴리즈 첨부 자산에 포함하지 않습니다. 게시된 최종 아카이브의 SHA-256은 GitHub 릴리즈 본문에서 확인합니다.

## 검증의 적용 범위
