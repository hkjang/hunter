# Hunter v1.16.0

목록의 **목록 주소 복사**가 저장한 보기의 브라우저 저장소 한도에 잘리지 않고, 보낸 사람이 보고 있는 결과를 그대로 가리키도록 고친 릴리즈입니다. 서버 API·권한·저장한 보기의 보관 규칙은 달라지지 않으며 일반 PostgreSQL·네 환경변수·서비스 Docker 이미지 하나의 기본 배포를 유지합니다.

## 사용자가 달라지는 점

- **복사한 주소가 내가 보던 목록을 엽니다.** 목록 도구의 **목록 주소 복사**는 주소를 `listSharePath`(`web/src/list-export.ts`)로 만드는데, 지금까지 저장한 보기와 같은 `savedListQuery`(`web/src/saved-list-views.ts`)를 그대로 썼습니다. 그 함수의 500 코드 단위 자르기는 `localStorage` 에 보기를 8개까지 보관하기 위한 한도이므로, 검색어나 필터 값이 500자를 넘으면 복사된 주소의 `q`·`f_*` 가 조용히 잘렸습니다. 받는 사람은 보낸 사람이 보던 것과 **다른 결과 집합**을 열게 됩니다. 이제 주소 복사만 자르기를 건너뛰므로 주소창이 담는 길이만큼 검색·필터 텍스트가 온전히 들어갑니다.
- **저장한 보기는 그대로 500자입니다.** `savedListQuery` 에 자르기 여부를 명시적으로 받는 인자를 추가했고 기본값은 기존 저장소 한도입니다. 주소 복사 경로만 이를 끕니다. 저장·복원이 같은 조건 문자열을 비교하는 동작, 사용자·메뉴별 최대 8개, 허용된 목록 조건만 보관하고 상세 ID·임의 URL 매개변수·폼 초안·비밀값을 저장하지 않는 규칙은 달라지지 않습니다.
- **주소에 담기는 항목은 늘어나지 않습니다.** 복사한 주소는 지금처럼 검색어, 허용된 열 정렬, 표시 수, 선언된 필터, 1보다 큰 페이지와 제품 탭만 담습니다. 이번 변경은 그 값들의 **길이**만 되돌린 것이고, 임의 매개변수를 통과시키거나 새 항목을 추가하지 않습니다.

## 운영 조건과 한계

받는 사람에게 보이는 결과는 언제나 그 사람의 현재 권한으로 서버가 판단합니다. 주소를 공유해도 자료 접근 범위가 넓어지지 않으며, 목록 안내 문구("받는 사람의 접근 권한에 따라 결과가 표시됩니다")도 그대로입니다. 주소 전체 길이는 브라우저와 사내 프록시의 URL 한도를 따르므로 아주 긴 검색어는 여전히 전달 경로에서 제한될 수 있습니다. 서버 API·권한·감사 기록은 바꾸지 않았고 관리자 설정 항목도 추가하지 않았습니다.

## 검증과 배포

`web/tests/convenience.test.mjs` 에 499자 뒤에 서러게이트 쌍(`🚀`)과 100자를 더한 입력으로 주소를 만들어 `q`·`f_service_id` 가 원문과 **같은 길이·같은 값**이고 대체 문자(`�`)가 생기지 않는 것을 확인하는 검사를 넣었습니다. 같은 검사가 저장한 보기 경로는 여전히 499자로 잘리는 것을 함께 확인합니다. `web/tests/saved-list-views.test.mjs` 는 저장과 복원이 같은 조건 문자열을 만드는 것을 추가로 고정합니다. 릴리즈 커밋에서 실행한 검사와 건너뛴 검사는 [검증 기록](validation.md)에 적었습니다.
